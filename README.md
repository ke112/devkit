# DevKit

DevKit 是一个原生 macOS 开发工具集合，包含 iOS 模拟器管理、图片叠加、制作证件照、去除图片水印、iOS App 发版、TinyPNG、Luban、WebP、媒体压缩和双色球选号。界面使用 SwiftUI，系统集成与图片处理使用 AppKit、ImageIO、AVFoundation 和 Foundation，Luban 图片压缩使用固定版本的 Luban 库。

## 功能

### 双色球选号

- 留空按下一期生成，或输入从 2003002 起的开奖期号，自动生成固定的 10 注。选号使用首期 2003001 至目标期前一期的开奖历史，相同的历史和目标期会生成同一组号码。此次扩充历史后，旧版本曾生成的号码可能变化。
- 10 注蓝球互不重复，任意两注红球最多重 1 个。在公平开奖、常规奖级下，至少中一注的概率为 **64.34%**，达到该预算下的理论上限。
- 右上角「策略测试」默认回测最近 100 个已开奖期，每期 10 注。在「每期注数」输入 1～1,000 的整数，按回车立即重算。展开期号可查看号码、奖级和奖金。报告汇总至少中一注的期数占比、投入、奖金与净收益，核奖未完成的期次标为待核对。
- 比较策略时可固定截止期和每期注数，复制报告留存每版结果。`LotterySimulation.run` 可传入策略名称和选号函数，函数接收目标期号、此前的开奖切片和每期注数。默认策略与按期选号页共用 `LotteryBacktest.makePortfolio`。
- 开奖后显示实际号码、逐注命中和奖级，以及按福彩公告核算的奖金。2026 年已核验的活动派奖按 10 注同打一张 20 元票计算，其他活动以当期公告为准。
- 红球升序展示，号码顺序不影响组合；每注金额为 2 元
- 根据上海福彩公布的常规开奖安排显示下次预计开奖时间，按北京时间展示，休市和临时调整以官方公告为准
- App 内置 2003001～2019151 共 2,510 期历史，2020001 期起从上海福彩增量同步。历史列表、走势图和按期选号使用拼接后的记录。旧期开奖公告缺失时，按档案中的一、二等奖单注金额和常规固定奖核算，单注浮动奖金缺失时显示待核对。
- 支持逐期号码列表和 XY 走势图，走势图以期号为横轴、号码为纵轴，红蓝球分别查看，可横向滚动并选择期号查看完整号码

双色球首期开奖日期为 2003 年 2 月 23 日。历史档案来自 500 开奖资料，逐期与旺彩年度表核对红蓝球和期号。两源有日期差异的 7 期在生成脚本中列出，日期仅用于展示。使用 `python3 scripts/build_ssq_archive.py devkit/Resources/ssq-2003-2019.csv` 可重新生成。[广东福彩首期记录](https://www.gdfc.org.cn/datas/content/content_255862.html) · [500 历史资料](https://datachart.500.com/ssq/history/newinc/history.php?start=03001&end=19151) · [旺彩年度表](https://h5.wcssq.cn/list/shuangseqiu/2003)

红球组合使用模 5 网格的直线构造。每条线含 5 个网格点和一个按方向共享的点，所以任意两条线只共享 1 个号码。一组开奖红球如果与两注各重 4 个，至少需要 7 个号码，因此每注覆盖的 5,428 种红球中奖结果互斥。10 个不同蓝球覆盖 10/16 的结果，其余 6 个蓝球下最多再覆盖 54,280 种红球结果。对全部 17,721,088 种结果枚举验证，共覆盖 11,401,360 种。10 注独立均匀机选的平均覆盖率为 50.07%。

历史验证使用 2020001～2026132 期。前 819 期探索红球重号、奇偶、区间、遗漏及蓝球频率、位移和大小区切换等 12 项规律，通过 999 组公平模拟和多重检验校正后，最低校正 p 值为 0.576。后 200 期逐期留出回测中，各规律的平均对数得分增益区间均包含零。固定随机种子的 10 注对照回测中，新组合有 129/200 期中奖，旧算法为 93/200，独立机选为 105/200。

新组合在公平开奖下的最高奖级概率依次为一等奖 0.000056%、二等奖 0.000846%、三等奖 0.009142%、四等奖 0.434228%、五等奖 7.71%、六等奖 56.19%。按常规奖级、忽略派奖，并用 2026133 期公告的浮动奖金额作为示例，10 注的回本概率约为 0.495%，期望奖金约 9.48 元。

### iOS 模拟器管理

- 按 iOS Runtime 分组展示本机模拟器、状态、UDID 和屏幕规格
- 自动刷新、手动刷新以及 CoreSimulator 异常恢复
- 启动、关闭、重置、删除和按原型号重建单个模拟器
- 为指定 Runtime 创建主流机型或全部受支持机型
- 批量删除 Runtime 下的模拟器，或连同 Runtime 镜像彻底删除
- 在 Finder 中打开模拟器目录，点击设备信息可复制到剪贴板

### 图片叠加

- 通过文件选择器或拖拽导入底图和上层图片
- 左右两个区域各自只取拖入的第一张图片；已有图片可通过“更换图片”替换
- 实时调节上层图片透明度并预览叠加结果
- 按底图原始像素尺寸导出 PNG
- 上层图片保持宽高比并居中适配底图画布

### 制作证件照

- 通过文件选择器选择单张照片，或直接拖入照片
- 多张照片一起拖入时默认只取第一张，不做批量处理
- 自动分离人物并替换背景，支持背景预览和导出 PNG

### 去除图片水印

- 通过文件选择器或拖拽导入单张图片
- 仅保留自动修复：从重复数字指纹水印提取笔画，再扫描整张图片，包括 OCR 漏识别的实例
- 对浅色背景上的半透明深色水印，结合局部背景与透明度反算修复，限制改动在匹配笔画内
- 修复结果保留原图尺寸，支持原图/结果切换、取消处理、还原和导出 PNG；不会覆盖原始图片
- 需要至少三处可匹配的重复水印及清晰参考笔画；不保证恢复不透明遮挡、复杂纹理或 JPEG 压缩前的原始细节

### TinyPNG 图片压缩

- 通过文件选择器或拖拽选择单张图片、多张图片、一个文件夹或多个文件夹
- 文件夹会递归扫描全部支持的图片；重复路径会自动去重
- 同一页面内多次拖入或选择会累加图片；返回首页后清空本页选择，重新进入需重新添加
- 调用项目内置 TinyPNG 脚本，支持 PNG、JPG、JPEG 和 WebP
- 固定版本的 Python 依赖安装到 `~/Library/Application Support/DevKit/Python` 下的独立环境，不修改共享 Python 包
- 默认自动替换原图；关闭开关后在输入路径同级生成带时间戳的输出目录，并保留原文件名和文件夹相对路径
- 上传前跳过超过 5 MB 的单张图片，避免触发 TinyPNG 限制
- 可配置最低压缩图片大小，默认仅压缩 100 KB 及以上的图片；设置会缓存到本地
- 通过“上传状态”面板查看每张图片状态、缩略图预览、原图路径和执行日志
- 显示总压缩前后大小、节省比例，以及每张图片的原始大小、压缩大小和节省比例
- 支持主动停止；离开压缩页面或 DevKit 退出时会终止压缩子进程
- 压缩进行中返回页面会先确认是否停止任务

### WebP 图片转换

- 通过文件选择器或拖拽选择单张图片、多张图片、一个文件夹或多个文件夹
- 文件夹会递归扫描全部支持的图片；重复路径会自动去重
- 同一页面内多次拖入或选择会累加图片；返回首页后清空本页选择，重新进入需重新添加
- 可配置转换质量、最低转换大小和最长边限制
- 默认自动替换原图；关闭开关后写入时间戳输出文件夹，仅当 WebP 更小时替换
- 支持上传状态、每张图片进度、执行日志和主动停止

### 媒体压缩

- 图片和视频共用一个页面，通过分段控件切换处理类型
- 图片支持 PNG、JPG、HEIC、WebP、TIFF、BMP、GIF、TGA、PSD；可设置目标大小和输出格式
- 图片压缩优先保持原格式，必要时自动尝试 HEIC/JPEG；无法达到目标时保留原图，避免丢失文件
- 视频支持 MP4、MOV、M4V 和高/中/低三档质量预设，按源视频分辨率选择不超过原尺寸的导出档位
- 支持拖拽、文件选择、文件夹递归、目录结构保留和批量去重
- 结果写入下载目录下的 `DevKit` 文件夹，可查看图片压缩前后对比并在 Finder 中定位文件
- 图片编码和视频导出在后台执行，支持主动停止；压缩后体积没有变小的视频会保留原文件

## 环境要求

- macOS 15.2 或更高版本
- 完整版 Xcode，并已安装所需 iOS Simulator Runtime
- Xcode Command Line Tools 指向完整 Xcode

如 simctl 无法使用，可执行：

~~~bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
~~~

## 构建与测试

使用 Xcode：

~~~bash
open devkit.xcodeproj
~~~

命令行构建：

~~~bash
xcodebuild \
  -project devkit.xcodeproj \
  -scheme devkit \
  -configuration Debug \
  -destination 'platform=macOS' \
  CODE_SIGNING_ALLOWED=NO \
  build
~~~

运行单元测试：

~~~bash
xcodebuild test \
  -project devkit.xcodeproj \
  -scheme devkit \
  -destination 'platform=macOS' \
  CODE_SIGNING_ALLOWED=NO
~~~

## 打包与安装

package_release.sh 会归档并校验 Release 应用，生成并保留以下产物：

- build/DevKit.zip
- /Applications/DevKit.app

打包完成并校验安装版后，脚本会删除项目目录和 Xcode DerivedData 中 Bundle ID 为 `com.zhihua.devkit` 的其他 `DevKit.app`，只保留 `/Applications/DevKit.app`。

执行：

~~~bash
./package_release.sh
~~~

脚本使用项目当前的 Apple Development 自动签名配置。当 /Applications 不可写时，安装阶段会请求 sudo。脚本不会自动启动应用。

当前产物未进行 Apple Notarization。将 ZIP 复制到其他 Mac 后，如果系统提示无法打开，可将应用放入 /Applications，再执行：

~~~bash
sudo xattr -r -d com.apple.quarantine /Applications/DevKit.app
~~~

## 操作风险

- “重置”会抹掉模拟器内的应用和数据，但保留设备及 UDID。
- “删除并重新创建”会删除原设备及数据，再按原设备型号和 Runtime 创建新设备；新设备会获得新的 UDID。
- “删除当前模拟器”不会自动创建替代设备。
- “彻底删除”会同时删除对应 iOS Runtime 镜像，通常会释放数 GB 空间。该操作不可撤销，重新使用时需要通过 Xcode 下载 Runtime。

执行删除或重建前，请确认目标 Runtime、设备名称和 UDID。

~~~text
devkit/
├── ContentView.swift

├── Features/
│   ├── ImageOverlay/
│   ├── WatermarkRemoval/

~~~

模拟器、图片叠加、去除图片水印、App Store 发版、TinyPNG、WebP 和媒体压缩模块按各自流程处理数据。去除图片水印、WebP 和媒体压缩模块在本机处理文件；TinyPNG 模块会将符合条件的图片上传到 TinyPNG 进行云端压缩；模拟器模块仅调用本机 Xcode 和 CoreSimulator 工具。
